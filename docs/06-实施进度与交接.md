### 2.2 修复的 6 个缺陷

#### 编译期 4 个

| 位置 | 问题 | 修法 |
|---|---|---|
| `KafkaEventSubscriber` | 用了 `MessageListener`，它只有 `onMessage(record)` 单参方法，拿不到 `Acknowledgment`，无法手动提交位点 | 改用 `AcknowledgingMessageListener` |
| `RabbitMqEventPublisher` ×2 | `MessageProperties.DELIVERY_MODE_PERSISTENT` 不存在 | 改用 `MessageDeliveryMode.PERSISTENT` |
| `RabbitMqEventSubscriber` | 同上 | 同上 |

#### 运行期 2 个（都是启动后才暴露，且都不报错或报错具有误导性）

**① JDBC URL 的 `characterEncoding=utf8mb4`**

Connector/J 要的是 **Java 字符集名**，不是 MySQL 字符集名。`utf8mb4` 在 Java 里不存在，
启动直接失败：`java.io.UnsupportedEncodingException: utf8mb4`。

```yaml
# 错
characterEncoding=utf8mb4
# 对
characterEncoding=UTF-8&connectionCollation=utf8mb4_general_ci
```

**② `RedisConfig` 把 `redisObjectMapper` 声明成了 `@Bean`** —— 本次最值得记的一个

`JacksonAutoConfiguration` 的 `@ConditionalOnMissingBean(ObjectMapper.class)` 是**按类型**
匹配的，不看 Bean 名。容器里一出现任何 `ObjectMapper` Bean，自动配置就整体退让，
于是这个开着 `activateDefaultTyping` 的 mapper 被三处同时拿走：

| 症状 | 表现 |
|---|---|
| Web 层 | 每个响应都带 `"@class"`，`Long` 被写成 `["java.lang.Long", 3]` |
| MQ 消息体 | 业务事件被套上类型包装 |
| 业务注入点 | 自检 `receivedAt` 恒为 null、`e2eMillis` 恒为 0 |

第三条最阴险：`JsonNode.asLong()` 对 `ArrayNode` **静默返回 0**，不抛任何异常。

**修法**：把该方法改成私有方法 `createRedisObjectMapper()`，在 `redisTemplate()` 里直接调用。
容器里只保留 Spring Boot 自动配置的 ObjectMapper（Web 与业务共用），Redis 用自己那个。

> ⚠️ **以后任何人想在 `RedisConfig` 里加 `ObjectMapper` Bean，先读这段。**
> 症状会出现在 Web、MQ、业务三个完全不同的地方，很难联想到根因在 Redis 配置。

### 2.3 一处判断被推翻（重要）

`ArchitectureTest` 的「Mapper 必须在 mapper 包下」规则，我起初给 infrastructure 加了例外，
理由是 `MqOutboxMapper` 与实体同包更内聚。

**随后发现 `@MapperScan("com.school.forum.**.mapper")` 扫不到它们**，Bean 注册不上、启动失败。

这说明：**那条 ArchUnit 规则和 `@MapperScan` 编码的是同一个约定**，我的例外等于让两处约定同时破例。
最终把两个 Mapper 移到 `mq/mapper` 包，撤销例外——两个约定都不必破，也和业务模块布局
（`entity/Post` 与 `mapper/PostMapper` 本就分居两包）一致。

> 记这条是因为：**给约定开例外之前，先找找还有谁依赖同一个约定。**

### 2.6 积分与积分商城（同日续作）

**需求**：签到得积分、当月签到超过 25 天额外赠送、签到用 Redis Bitmap 实现、
积分商城只有管理员能改内容而普通用户只能下单。流程按要求**先改文档再写代码**：

**新增模块 `forum-points`**（`api / controller / service / service·impl / mapper / entity / dto / vo / convert / task / support`）：

- 实体/Mapper 5 个；手写 XML 3 个（游标分页、全勤名单的游标分批、跨两月的位图取数）
- `SigninService`：`signin.lua` 一条命令完成「置位 + 幂等判断 + 回读天数」。
  **用 `SETBIT` 的返回值做幂等**，不是先 `GETBIT` 再 `SETBIT`——后者在并发下两个请求都会
  认为「今天还没签」，只能靠异常路径兜底，而幂等应当是正常返回
- `PointsAccountService`：**所有积分变动的唯一出口**。加分、扣分都是条件 UPDATE
  （`WHERE balance >= ?`），不做「先查再改」；每笔变动必写 `t_points_record`
- `MallGoodsService` / `MallOrderService`：下单 = 扣库存 → 扣积分 → 写订单，三步任一失败整体回滚；
  取消 = 先 `markCancelled`（状态机当闸门，防重复退款）→ 还库存 → 退积分
- `PointsAdminApiImpl`：每天 00:10 结算上月，Redisson 锁 + 每人一个独立事务（不放大事务），
  幂等靠 `uk_user_biz` 而非进度记录
- `SigninBitmapRepairTask`：每天 04:00 按 `t_user_signin` 重建近两个月位图。
  写入走 `executePipelined`（一轮一次往返），每轮 `SETBIT → EXPIRE → BITCOUNT`——
  顺序不能变，最后那条 `BITCOUNT` 才看得到本次写入

**权限边界**：`@RequireRole(ROLE_ADMIN)` 加在 `AdminMallController` / `AdminPointsController`
**类上**而不是方法上，这样以后新加管理接口默认就是受保护的，忘记加注解的后果从
「接口裸奔」变成「接口访问不了」——后者在自测时立刻暴露。用户侧 `MallController` 里
**没有任何管理能力**，不是靠判断拦住的。前端的 `requiresAdmin` 守卫只影响界面显示，
注释里写明了它不是安全边界。

### 2.7 积分秒杀（本轮实现）

**决策**：秒杀入口放在积分商城页面，与普通兑换**并列但完全分开**；用**积分支付**、
保留「待支付 + 15 分钟超时」、取消后**不能重抢**、消息走 **Kafka**。
四条决策的理由见《02-架构设计》ADR-010 与《03-功能设计》第 6 节（本节只记实现落点）。

| 环节 | 落点 |
|---|---|
| 抢购（Lua 预扣 + 幂等重放 + 写 outbox） | `SeckillServiceImpl.grab`、`resources/lua/seckill_grab.lua` |
| 异步落库（扣 DB 库存 + 建单 + 投超时延迟消息） | `SeckillServiceImpl.createOrder`、`SeckillOrderEventHandler` |
| 支付（扣积分 + `locked → sold`） | `SeckillServiceImpl.pay` + forum-points 的 `PointsSpendApi` |
| 超时取消（延迟消息 + 定时扫描兜底） | `SeckillTimeoutEventHandler`、`SeckillTimeoutScanTask` |
| 预热与状态刷新 | `SeckillWarmupTask`（`SETNX` 写库存、每次刷新快照） |
| 库存对账（口径 `Redis == available_stock`） | `SeckillStockReconcileTask`（跳过进行中的活动） |

**两个不显然的实现决定**：

1. **Redis 写入全部落在数据库事务之外**。`SeckillServiceImpl` 刻意**不用** `@Transactional`，
   改用 `TransactionTemplate` 圈出纯 DB 动作。《04》6.1 把「事务中禁止 Redis 写」列为硬性
   禁止事项，而本模块的时序恰好是「Redis 在前、DB 在后」（抢购必须先扣 Redis），
   注释给不了这个粒度——这是全项目第一个需要它的地方。
2. **取消时删「分配键」、但保留 `bought` 计数**。前者让再次抢购落到限购判定（15002），
   后者让限购真的生效。两个 key 一删一留，原因写在《03》§6.6。

**实现中发现并修正的一处设计漏洞**：最初只想到「取消不删用户标记」，却忘了删「分配键」，
于是用户取消后再点抢购会命中 Lua 的幂等重放、拿回同一张**已取消**的单——
界面上看起来像「点了没反应」。**只有把流程完整走一遍才会暴露**，静态看设计看不出来。

**验证状态（不要误读）**：

- ✅ `mvn -pl forum-boot -am test -Dtest=ArchitectureTest` → **8/8 通过**
  （MQ 抽象未被击穿、无循环依赖、admin 只走 api 包、Mapper 位置正确）；全量编译通过。
- ✅ `python smoke/e2e-seckill.py` → **48/48 全绿**，且是**真实 Kafka**（`--spring.profiles.active=mq-kafka`）
  跑出来的，不是 mock。覆盖：未预热 15005 / 未开始 15003 / 抢光 15001 / 幂等重放同一单号 /
  取消后 15002 / 支付扣分与 `locked → sold` / 积分不足 16002 / 重复支付与重复取消 15013 /
  10 并发一人一单 / 超时自动关闭并回补 / 权限 10003。
  交付时后端已停止，**没有留下运行中的进程**；DB 里留下了本次冒烟创建的活动与订单
  （彼此自洽，不必清理；要干净环境就重新导入 `sql/01` + `sql/02`）。

**跑冒烟时抓出的两个真 bug（都是「只有真跑一遍才会现形」的类型）**：

1. **管理端建活动必失败**：`SeckillActivityForm` 的 `LocalDateTime` 入参只认 ISO-8601
   （`2026-09-17T22:00:00`），而前端 `el-date-picker` 提交的是 `2026-09-17 22:00:00`。
   根因是 `spring.jackson.date-format` **对 `LocalDateTime` 不生效**，它只管 `java.util.Date`。
   报错是 10001「请求格式不正确」，字面上完全看不出是时间格式问题。
   修法：在字段上显式加 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")`。
2. **未开始的活动返回了 15005 而不是 15003**：快照缺失时我统一返回「活动太火爆」，
   但「未开始」是一个**正常状态**——预热窗口从「开始前 N 分钟」起算，
   所以未开始的活动恒定没有快照。修法：快照缺失时走一次查库的冷路径，
   把「未开始 / 已结束 / 真没预热」分开报。

## 三、必须遵守的约定（新增代码时）

1. **业务模块不得直接依赖任何 MQ 客户端。**
   发消息用 `EventPublisher`，收消息实现 `EventHandler`。
   不写 `@KafkaListener`，也不写 `@RabbitListener`——**ArchUnit 会让构建失败**。
   理由：只要有一个业务类沾上产品注解，切换 MQ 就要改代码，两次压测的结果就不可比。

2. **跨模块只能调用对方的 `api` 包**，不得引用对方的 `entity` / `mapper` / `service`。
   `forum-admin` 是唯一依赖其他业务模块的模块。

3. **Mapper 接口必须放在 `mapper` 包下。** 这条不是审美，是 `@MapperScan` 的要求（见 2.3）。

4. **MQ 只承诺 at-least-once**，消费端必须自己保证幂等。
   快路径用 `IdempotentGuard`（Redis SETNX，故障时放行），真正的防线是数据库唯一索引。

5. **写新的 `EventHandler` 时参考 `SelfTestEventHandler`** —— 它是最小可用的模板。

## 六、环境坑（Git Bash）

- `docker exec <容器> /opt/...` 会被 MSYS 改写成 `C:/Program Files/Git/opt/...`
  → 必须 `export MSYS_NO_PATHCONV=1`
- **Windows 的 Python 读不了 `/tmp/...`**，但 curl 写 `/tmp/...` 正常
  → 给 Python 分析的临时文件要落在 `C:\work\...` 下
- **`docker exec ... mysql` 查中文显示 `??????`**（已修，非待办）
  - 现象：表注释、种子数据查出来全是 `??????`，但 `sql/*.sql` 文件本身没问题。
  - 定性：**客户端字符集**问题，不是数据坏了——`SELECT HEX(列)` 能看到字节是好的。
  - 根因：mysql 客户端不指定字符集时按进程 locale 推导，容器没设 `LANG` → locale 为 C
    → 退化成 latin1。
  - 真正的危害不止「看着乱」：`docker-entrypoint.sh` 用的就是同一个客户端，
    所以**首次初始化导入**会把 `01-schema.sql` 里的中文按 latin1 解释后双重编码写进库
    （实测 `论坛板块表` 的 `E8AEBA...` 被存成 `C3A8C2AE...`），且**全程不报任何错**。
    也就是说 `down -v` 重建一次，库里的 DDL 中文就真坏了——这才是「库里的 DDL 是乱码」
    这一类反馈的来源。
  - 修法：compose 的 mysql 服务加 `LANG: C.UTF-8`（客户端默认即 utf8mb4），
    查看与导入两条路一起解决，不必再给每条命令手加 `--default-character-set=utf8mb4`。
  - 走过的弯路：本想挂载 `/etc/mysql/conf.d/*.cnf` 写 `[client] default-character-set`，
    但 Windows 绑挂载的文件权限是 `0777`，MySQL 判定 world-writable 后
    `World-writable config file ... is ignored` **静默忽略**，配了等于没配。
  - 宿主机原生客户端（`mysql -u root -p < sql/...`）**仍需**手加
    `--default-character-set=utf8mb4`，Windows 上它默认走 GBK。
- 8080 常常被 IDE 里启动的实例占着。冒烟测试请换端口跑（`--server.port=8081`），
  否则杀进程就会把别人正在调的那个实例一起杀掉
- `taskkill //PID <pid> //F` 里的双斜杠在 Git Bash 下会被原样传给 taskkill 而报
  「无效参数」——要么 `export MSYS_NO_PATHCONV=1` 后用单斜杠 `/PID`，
  要么干脆别在 Git Bash 里调 Windows 原生命令
- **`docker exec -i` 会偷走 while 循环的标准输入**：
  `redis-cli --scan | while read k; do docker exec -i redis redis-cli DEL "$k"; done`
  只删掉第一条就退出——`-i` 让容器进程吃掉了循环本该读的管道。
  正确做法是一次性把 key 都传给 `DEL`，或给容器调用加 `< /dev/null`

## 七、三个「报错信息与病因对不上」的陷阱

都不在业务逻辑里，但报错信息极具误导性，值得单独记一笔：

1. **`YEAR_MONTH` 是保留字**（INTERVAL 的单位之一），裸写 `year_month` 直接语法错误。
   本项目 `t_user_signin` 用了这个列名，因此手写 SQL 必须写 `` `year_month` ``，
   实体上必须 `@TableField("`year_month`")`——只改一处会导致另一处炸。
2. **`SqlCommandType` 取自注解而不是 SQL 文本**。把 `INSERT IGNORE` 写在 `@Update` 下，
   `BlockAttackInnerInterceptor` 会把它当 UPDATE 送进 JSqlParser，
   解析出 Insert 节点后落到默认实现，抛一句与 INSERT 毫无关联的
   `UnsupportedOperationException`。写 INSERT 就用 `@Insert`（或 XML 的 `<insert>`）。
3. **接口路径写错会报 50000「服务器内部错误」，而不是 10004「请求的资源不存在」。**
   Spring Boot 3.2（Spring Framework 6.1）起，缺省注册的 `ResourceHttpRequestHandler`
   接管了 `/**`：访问不存在的路径时 DispatcherServlet **找得到 handler**（就是这个资源处理器），
   只是它找不到资源，于是抛的是 `NoResourceFoundException`——
   与 `GlobalExceptionHandler` 里那个 `NoHandlerFoundException` **是两个不同的类**，
   于是原先写的 10004 处理器从来没被触发过，异常一路掉进 `Exception` 兜底，
   被打成 `ERROR 系统异常` 并记全堆栈。**已修**：补了
   `@ExceptionHandler(NoResourceFoundException.class)`，现在照常返回 10004，
   日志是单行 `WARN 接口或资源不存在。uri=...`。

   这个坑真正的代价不是错误码难看，而是**它会误导排查方向**：
   本次就因为「8080 那个旧实例访问 `/points/*` 返回 50000」，
   一度判断成「旧代码在跑、只是有 bug」，实际那个实例**根本没有 points 路由**——
   50000 只是 404 的另一种写法。判据很简单：
   随便打一个肯定不存在的路径做对照，如果响应**一模一样**，那就是路由缺失而非运行时异常。
